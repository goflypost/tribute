# Probe

**Question:** Does onboarding learn what I need, or dump me somewhere empty?

## Mission

Follow the primary call to action. Go as far as a first-time user would before
doing real work: sign-up screen, onboarding steps, or straight into the
product. Note what the app asks you, whether each question earns its place,
and what state you land in — a guided start, a sensible default workspace, or
an empty screen with no direction. If sign-up requires payment or personal
information beyond the test identity, stop there and record it.

Max 20 actions.

## Scoring anchors

- **5** — The app meets you where you are: it asks only what it needs, uses
  the answers visibly, and lands you in a state with an obvious first action
  (template, sample data, guided step). A no-onboarding app lands you directly
  in a usable, self-explanatory workspace.
- **4** — Smooth start with small friction: one unnecessary question, or a
  landing state that's usable but undirected.
- **3** — Functional but indifferent: generic sign-up, no personalization,
  empty-but-labeled starting state. You can proceed, but the app learned
  nothing about you.
- **2** — Onboarding is a wall: demands an account before showing any value,
  asks questions it never uses, or dumps you somewhere empty with no clue what
  to do first.
- **1** — Onboarding is broken: sign-up errors, dead confirmation flows,
  or the first screen after entry is a settings page, an error, or a blank.
